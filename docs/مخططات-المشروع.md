# مخططات المشروع — PhoneAccounting (casher1)

مخططات مرئية مولَّدة من الكود مباشرة (Mermaid) لتوثيق بنية المشروع وقاعدة البيانات ومسارات العمليات.

**طريقة العرض:**
- على GitHub: تُعرض تلقائياً داخل صفحة Markdown.
- محلياً: إضافة `Mermaid` لامتدادات VS Code، أو https://mermaid.live لعرض/تصدير.
- مخطط معماري تلقائي عبر https://gitdiagram.com/ar-kn/casher1

> جميع المخططات أدناه مبنية على مصدر المشروع الحالي (`App.xaml.cs`، `MainViewModel.cs`، `AppDbContext.cs`، `PosViewModel.cs`، `RepairReceiveViewModel.cs`، `Services/Sync/*`).

## 3) المخططات التسلسلية (Sequence)

### 3.1 عملية البيع من نقطة البيع

```mermaid
sequenceDiagram
    autonumber
    actor U as "الكاشير"
    participant W as "PosWindow"
    participant VM as "PosViewModel"
    participant DDL as "CloseDayService"
    participant INV as "InvoiceService"
    participant CTX as "AppDbContext"
    participant OP as "OperationWriter"
    participant DB as "SQLite"

    U->>W: يبحث عن منتج ويضيفه إلى السلة
    W->>VM: AddToCart
    VM->>VM: RefreshTotals و RefreshUnderReviewFlags
    U->>W: يضغط حفظ أو حفظ وطباعة
    W->>VM: SaveSale

    VM->>DB: فحص المخزون لكل بند
    DB-->>VM: الكمية المتوفرة
    alt الكمية أكبر من الرصيد
        VM-->>U: رسالة خطأ وتوقف
    end

    VM->>DDL: IsLocked تاريخ الفاتورة عند التعديل
    DDL-->>VM: مقفل أو مفتوح

    VM->>INV: NextSaleNumber ثم SaleInvoiceNumber
    INV-->>VM: رقم فاتورة فريد لليوم والجهاز

    VM->>CTX: بناء Sale و SaleItems وخصم Stock وتحديث Balance عند الآجل
    VM->>OP: Register نوع Sale أو SaleEdit
    OP->>CTX: إضافة صف OperationLog بـ Seq يساوي صفر

    CTX->>CTX: SyncWriteLock.Acquire لمنع تداخل الدلتا مع الحفظ
    CTX->>CTX: AssignSyncFields تعبئة SyncId و OriginDevice
    CTX->>CTX: AssignPendingOpSeqs منح Seq لحظة Commit
    CTX->>DB: SaveChanges داخل معاملة واحدة
    alt تعارض رقم الفاتورة
        DB-->>CTX: DbUpdateException
        CTX->>VM: إعادة توليد الرقم حتى خمس محاولات
        CTX->>DB: SaveChanges مجدداً
    end
    DB-->>VM: تم الحفظ

    VM-->>U: تم تسجيل الفاتورة رقم و الإجمالي
    opt طباعة
        VM->>W: PrintSale عبر ReportPrinter
    end

    Note over CTX,DB: سجل العملية والفاتورة والمخزون تُحفظ في عملية واحدة
    Note over VM,DB: خلفياً SyncScheduler يرسل دلتا التغييرات إلى الأجهزة الأخرى
```

### 3.3 المزامنة بين الأجهزة (نظير لنظير عبر TCP)

```mermaid
sequenceDiagram
    autonumber
    participant SCH as "SyncScheduler"
    participant A as "الجهاز المحلي"
    participant P as "SyncPeer TCP"
    participant B as "الجهاز الزميل"
    participant CTL as "ResolveView على MAIN"

    Note over SCH: دورة دورية كل SyncIntervalMinutes دقيقتها خمس
    SCH->>P: اتصال بمعرف الأقران الثابتة
    P->>B: Hello مع DeviceId و السر و SchemaVersion
    alt السر أو الإصدار مختلفان
        B-->>P: رفض مبكر وتسجيل المحاولة
    end

    P->>B: خريطة علامات ماء آخر ما نُفّذ
    B->>B: DeltaBuilder.BuildFor لبناء الناقص
    B-->>P: حزمة دلتا أصلية وممرّرة
    P->>P: DeltaApplier.Apply بأسلوب idempotent
    P->>B: دلتا محلية بنفس خريطة الزميل
    B->>B: تطبيق الدلتا وتحديث SyncPeerState

    Note over P,B: العمليات بـ OriginDevice البعيد لا تُعاد إليه منعاً للإرجاع

    alt اختلاف في نفس SyncId
        B->>B: SyncConflictService يسجّل صراعاً في SyncConflicts
        CTL->>CTL: قرار MAIN KeepLocal أو KeepRemote أو StaysDeleted
        CTL->>B: عملية ConflictResolution موقّعة تُغلق الصراع
    end

    opt فشل اتصال
        P->>P: تراجع أسّي 1s في الثانية حتى خمس دقائق
    end
```

## 4) مفتاح الرموز

| الرمز | المعنى |
|---|---|
| `\|\|--o{` | واحد إلى كثير (علاقة أب/تاجر إلزامية) |
| `ProductId مرجعي` | مرجع منطقي دون مفتاح خارجي معرَّف في EF |
| `Seq يُمنح عند Commit` | الترقيم يحدث داخل `AppDbContext.SaveChanges` لا عند الإنشاء |
| `DeletedAt` | حذف ناعم — الصف يبقى ويُستبعد من الاستعلامات |
| `SyncId + OriginDevice` | هوية الصف عبر الشبكة ومانع الإرجاع echo |
